# Модуль 7. Управление клиентами

> Просмотр основной информации о покупателях, их заказах и внутренних заметках. Не CRM — без сегментов, лояльности, бонусов.

## Ключевое разграничение

- **Зарегистрированная учётная запись** — покупатель может войти на сайт.
- **Внутренний профиль покупателя** — создаётся системой автоматически (регистрация или оформленный заказ); не требует учётной записи.

Гостевой заказ (без регистрации) всё равно создаёт внутренний профиль.

## 1. Список клиентов

Колонки: имя и фамилия, телефон, email, наличие учётной записи, кол-во выполненных заказов, общая сумма покупок, средняя сумма выполненного заказа, дата последнего заказа, наличие внутренней заметки.

**Правила расчёта:**

- Кол-во заказов / общая сумма / средний чек — считаются **только** по заказам со статусом «Выполнен» (см. [`orders.md#5-статусы-заказа`](./orders.md#5-статусы-заказа)).
- Общая сумма покупок = стоимость товаров **после скидок**, **без** стоимости доставки.
- Средний чек = общая сумма покупок / кол-во выполненных заказов; если выполненных заказов нет — не считается (не 0, а «нет данных»).
- Дата последнего заказа — по последнему **созданному** заказу, независимо от статуса.
- Заказы «В обработке», «Готов к выдаче», «Отменён» — **не** входят в статистику покупок, но остаются в полной истории заказов клиента.
- Правила учёта частичного/полного возврата денег — будут определены в модуле «Оплата» (вне текущего документа).

## 2. Поиск, фильтрация и сортировка

- **Поиск:** имя/фамилия, телефон, email.
- **Фильтры:** есть выполненные заказы / нет выполненных заказов / есть внутренняя заметка / нет внутренней заметки.
- **Сортировка по умолчанию:** дата последнего заказа, от новых к старым; клиенты без заказов — в конце списка.
- **Доступные сортировки:** имя, кол-во выполненных заказов, общая сумма покупок, дата последнего заказа.
- Сложная сегментация (по товарам/категориям/поведению) — не требуется.

## 3. Профиль клиента

Отображает: имя, фамилию, телефон, email, наличие учётной записи, дату регистрации (если есть аккаунт), сохранённые адреса (если есть аккаунт), кол-во выполненных заказов, общую сумму покупок, средний чек, дату последнего заказа, полную историю заказов (все статусы), внутреннюю заметку.

- Из истории заказов можно открыть конкретный заказ на просмотр/обработку.
- Сохранённые адреса показываются **только** при наличии учётной записи; для гостя адрес хранится только в самом заказе (нет отдельного списка адресов).
- Изменение/удаление клиентом своих данных в аккаунте **не** ретроактивно меняет данные, уже сохранённые в оформленных заказах (тот же принцип снапшота, что в [`orders.md#3-информация-сохраняемая-в-заказе`](./orders.md#3-информация-сохраняемая-в-заказе)).

## 4. Создание внутреннего профиля

- Ручное создание клиента/аккаунта в админке — не требуется.
- Профиль создаётся автоматически: при регистрации, при оформлении первого заказа, при корректном связывании последующих заказов.
- Перед созданием нового профиля — проверка на существующий с совпадающими нормализованными телефоном/email.
- Нормализация: email — без учёта регистра и пробелов; телефон — единый формат без пробелов/скобок/дефисов.

## 5. Связь заказов с клиентом

- Гостевой заказ автоматически привязывается к существующему профилю **только** при одновременном совпадении нормализованного телефона **и** email.
- Совпадение только одного поля → без автообъединения.
- Неоднозначность / несколько кандидатов → создаётся отдельный профиль, без автообъединения.
- Ручное объединение дублей — не требуется на первом этапе.
- Связывание используется для работы администратора; это не обязывает автоматически показывать все прошлые гостевые заказы клиенту в личном кабинете (нужна доп. проверка личности).

## 6. Редактирование данных клиента

**Администратор НЕ редактирует** в профиле клиента: имя, фамилию, телефон, email, сохранённые адреса — это редактирует только сам клиент в своём аккаунте.

- Если нужно поправить контактные данные/адрес для **конкретного заказа** — правка делается в карточке заказа (правила [`orders.md#7-ограничение-редактирования-заказа`](./orders.md#7-ограничение-редактирования-заказа)), и это **не** затрагивает аккаунт клиента или другие заказы.

## 7. Внутренняя заметка

- Одна заметка на профиль (не история версий). Хранит: текст, дату/время последнего изменения, администратора, который изменил.
- Видимость: в профиле клиента + при просмотре его последующих заказов. **Не** видна клиенту, не в email, не в печатной версии заказа (согласуется с [`orders.md#9-комментарии-и-заметка-о-покупателе`](./orders.md#9-комментарии-и-заметка-о-покупателе)).

## 8. Пароль и восстановление доступа

- Администратор **не может**: видеть пароль, устанавливать новый, менять существующий.
- Если клиент не может войти — администратор отправляет стандартную ссылку сброса пароля на email; новый пароль клиент задаёт сам. Отправка ссылки сама по себе пароль не меняет.

## 9. Ограничения (явно не требуется на первом этапе)

- блокировка клиента;
- запрет на оформление заказов;
- ручное изменение данных аккаунта администратором;
- ручное объединение дублирующихся профилей;
- группы/сегменты клиентов;
- уровни лояльности, бонусные баллы;
- отдельная CRM-система.

Информация о проблемном покупателе — фиксируется во внутренней заметке (§7).

## 10. Удаление и персональные данные

- Зарегистрированную учётную запись клиента через этот модуль администратор **не** удаляет.
- Внутренний профиль **без** учётной записи и **без** связанных заказов — можно удалить после подтверждения.
- Профиль, связанный хотя бы с одним заказом — удалить напрямую нельзя (история заказов должна сохраняться).
- Порядок обработки запросов на удаление/обезличивание персональных данных — будет определён отдельно (GDPR/аналог, вне текущего документа).
