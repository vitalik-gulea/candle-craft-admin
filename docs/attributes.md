# Модуль 6. Управление атрибутами и фильтрами

> Централизованное управление характеристиками товаров, вариациями, фильтрами каталога и производителями. Атрибуты и значения создаются один раз и переиспользуются — повторный ввод для каждого товара не требуется.
>
> Расширяет / уточняет [`products.md#7-характеристики-и-вариации`](./products.md#7-характеристики-и-вариации) — там был описан упрощённый взгляд на характеристики, здесь — полная модель атрибутов с областями использования.

## 1. Управление атрибутами

Действия: создавать, редактировать, активировать/деактивировать, менять порядок, удалять неиспользуемые.

Поля атрибута:

- [ ] название (RO/RU)
- [ ] тип атрибута (см. §2)
- [ ] разрешённые области использования (см. ниже)
- [ ] статус

**Области использования** (независимые флаги, один атрибут может числиться сразу в нескольких):

- для создания вариаций;
- в характеристиках товара;
- как фильтр в каталоге.

Пример: атрибут «Объём» может одновременно определять вариации, отображаться в характеристиках и быть фильтром.

- Название атрибута уникально отдельно для RO и RU; при проверке уникальности регистр и лишние пробелы игнорируются.
- Тип атрибута и область использования **нельзя менять**, если это нарушит структуру уже существующих товаров/вариаций — система должна явно сообщить причину («атрибут уже используется»).

## 2. Типы атрибутов

### 2.1. Атрибут с предустановленными значениями

- Значения создаются заранее, выбираются при редактировании товара.
- Примеры: объём (30/80/120 ml), вес (10/15 g), цвет, материал, тип фитиля, совместимость с воском.
- Может использоваться: для вариаций, в характеристиках, как фильтр.
- Для одного товара можно выбрать **несколько** значений одного атрибута, даже если атрибут не используется для вариаций (пример: товар совместим и с соевым воском, и с парафином).

### 2.2. Характеристика со значением, указанным в товаре

- Название характеристики — централизованное, значение вводится прямо в карточке товара (свободный ввод).
- Примеры: температура плавления (46–50°C), рекомендуемый % ароматизатора (6–10%), температура заливки (55–60°C).
- Используется **только** для отображения информации о товаре — **не** для вариаций и **не** для фильтров.
- В одном товаре одну и ту же характеристику можно добавить только один раз.

## 3. Управление значениями атрибутов

Для атрибутов с предустановленными значениями:

- добавление значений (RO/RU), редактирование, активация/деактивация, drag & drop порядок, удаление неиспользуемых.
- Уникальность значения — в пределах атрибута, отдельно RO/RU, без учёта регистра/пробелов (нельзя два раза «30 ml» внутри «Объём»).
- Значение хранится вместе с единицей измерения как единая строка (`30 ml`, `10 g`) — **отдельный справочник единиц измерения для атрибутов не нужен** (не путать со справочником единиц продажи товара, см. [`products.md#8-единицы-продажи`](./products.md#8-единицы-продажи) — это разные сущности).
- Порядок значений, заданный администратором, — дефолтный порядок везде: выбор вариации на странице товара, отображение характеристик, фильтры каталога.
- Переименование атрибута/значения автоматически отражается везде, где оно используется (товары, фильтры) — без ручной синхронизации.

## 4. Использование атрибутов в товаре

При редактировании товара администратор комбинирует:

- атрибуты с одним значением;
- атрибуты с несколькими значениями;
- характеристики со свободным значением (§2.2);
- атрибуты для вариаций.

Порядок характеристик на странице конкретного товара — настраивается вручную (пример: для воска — тип воска → температура плавления → % ароматизатора; для ёмкости — материал → объём → размеры; для фитиля — материал → размер → рекомендуемый диаметр свечи).

## 5. Использование атрибутов для вариаций

- Только атрибуты с предустановленными значениями и флагом «разрешено для вариаций» (см. §1).
- Администратор выбирает атрибуты-формирователи вариаций, их значения и **конкретные комбинации**.
- **Важно:** система не генерирует автоматически все комбинации значений (декартово произведение) — создаются только те, что администратор явно добавил/подтвердил.
  - Пример: объём {30ml, 80ml} × цвет {белый, жёлтый} → возможны 4 комбинации, но публикуются только реально существующие.
- Для каждой созданной вариации — стандартный набор полей из [`products.md#72-создание-вариаций`](./products.md#72-создание-вариаций): внутренний ID, SKU, цена, остаток, изображение, статус активности.

## 6. Отображение вариаций в фильтрах

- Если атрибут используется для вариаций — товар участвует в фильтрации по значениям **всех своих активных вариаций** (пример: вариации 30ml и 80ml → товар показывается при выборе любого из этих значений в фильтре «Объём»).
- Вариация, отключённая администратором, в фильтрах не учитывается.
- Вариация с нулевым остатком **может** учитываться в фильтре, пока остаётся видимой со статусом «Нет в наличии» (согласуется с [`products.md#74-активность-и-наличие-вариации`](./products.md#74-активность-и-наличие-вариации)).

## 7. Настройка фильтров для категорий

- Фильтры **не** показываются автоматически во всех категориях — это настройка на уровне каждой категории:
  - выбор, какие атрибуты используются как фильтры именно в этой категории;
  - вкл/выкл отдельных фильтров;
  - порядок фильтров drag & drop.
- Примеры привязки: «Объём» → ароматизаторы; «Вес» → красители; «Тип фитиля» → фитили; «Материал» → ёмкости/формы; «Совместимость с воском» → красители/ароматизаторы.
- В фильтре показываются только значения, по которым **фактически есть товары** в данной категории.
- Если категория показывает товары из подкатегорий (флаг из [`categories.md#5-связь-категорий-с-товарами`](./categories.md#5-связь-категорий-с-товарами)) — фильтры/значения считаются по всем товарам, реально отображаемым на странице.

## 8. Логика фильтрации

- Внутри одного фильтра — множественный выбор значений, между ними — **ИЛИ** (например, объём 30ml ИЛИ 80ml).
- Между разными фильтрами — **И** (например, объём 30ml И производитель Iberchem).
- Значения без товаров в текущей категории — скрыты.
- Выбранные фильтры остаются активными, пока покупатель не снимет их вручную.
- UI должен поддерживать: снятие одного значения, сброс всех фильтров, просмотр списка активных фильтров.

## 9. Фильтр по цене

- Не создаётся вручную как атрибут — отдельный встроенный механизм.
- Мин/макс диапазон рассчитывается автоматически по ценам товаров, доступных в категории.
- Для товаров с вариациями — учитываются актуальные цены активных вариаций (диапазон, см. [`products.md#101-цена-и-скидка-товара-с-вариациями`](./products.md#101-цена-и-скидка-товара-с-вариациями)).

## 10. URL и SEO для фильтров

- Выбранные фильтры/диапазон цены/результаты — сохраняются в параметрах URL, переживают reload, работают с кнопками браузера «назад/вперёд».
- Страницы с параметрами фильтрации:
  - **не** в sitemap;
  - **не** получают отдельные SEO Title/Meta Description;
  - **не** создают отдельные индексируемые страницы.
- Canonical всегда указывает на основную страницу категории без параметров фильтра (аналог правила для вариаций товара, [`products.md#73-выбор-вариации-и-canonical-url`](./products.md#73-выбор-вариации-и-canonical-url)). Ручное поле canonical для фильтров не нужно.

## 11. Деактивация атрибутов и значений

- Деактивированный элемент **сохраняется** в товарах, где уже используется:
  - продолжает отображаться в существующих товарах;
  - остаётся выбранным при редактировании такого товара;
  - **нельзя** назначить другому товару;
  - **нельзя** использовать для новых вариаций;
  - не предлагается как доступный вариант для нового выбора.
- Администратор может вручную убрать деактивированный элемент из конкретного товара.
- Если деактивированное значение — часть **активной** вариации, система должна предупредить о необходимости проверить эту вариацию.

## 12. Удаление атрибутов и значений

- Неиспользуемый атрибут/значение — удаляется после подтверждения.
- Используемый (в товарах/вариациях) — удалить напрямую **нельзя**. Порядок: убрать из товаров → проверить связанные вариации → убедиться, что не используется в фильтрах категорий → тогда можно удалить. До этого — только деактивация.

## 13. Управление производителями

Отдельный справочник в этом же модуле.

- Действия: добавление, редактирование названия, активация/деактивация, выбор при редактировании товара, использование как фильтра, удаление неиспользуемого.
- Название уникально (без учёта регистра/пробелов).
- Для одного товара — **только один** производитель.
- В фильтре — алфавитный порядок (ручная сортировка не нужна).
- Производитель, связанный с товарами, нельзя удалить напрямую — сначала убрать из товаров, до этого — только деактивация.
- Деактивированный производитель остаётся в существующих товарах, но не выбирается для новых.
- **Не требуется на этом этапе:** публичная страница производителя, логотип, описание, контакты, SEO-настройки.
- Страна происхождения (если нужна) — не поле производителя, а отдельная характеристика товара (§2.2).

## 14. Список атрибутов в административной панели

Желательные колонки: название, тип, области использования, кол-во значений, кол-во связанных товаров, статус.

Действия из списка: редактировать, менять статус, менять порядок, перейти к значениям, удалить (если нигде не используется).

**Явно не требуется на первом этапе:** сложные группы атрибутов, автогенерация SEO-страниц под фильтры, изображения значений/цветовые образцы, отдельные страницы производителей.
