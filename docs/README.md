## Сквозные принципы (действуют в обоих модулях)

- **RO/RU везде раздельно**: название, URL, описание, SEO Title, Meta Description, ALT — отдельные поля для каждой языковой версии, без авто-копирования одного в другое.
- **URL / slugify**: генерируется автоматически при создании (латиница + транслитерация кириллицы + румынской диакритики), после создания редактируется вручную; смена названия НЕ меняет уже опубликованный URL автоматически.
- **301/410 при смене или удалении URL**: старый URL всегда редиректит напрямую на текущий (без цепочек), циклы запрещены; при окончательном удалении — 301 на указанную страницу или 410, без авторедиректа на главную.
- **Уникальность URL / SKU / SEO Title**: проверяется в пределах языковой версии; при конфликте — блокирующая ошибка (SEO Title — только предупреждение, не блокирует).
- **Корзина (soft delete)** перед окончательным удалением, с проверкой связанных сущностей (товары, подкатегории, редиректы) и явным предупреждением администратору.
- **WYSIWYG-редактор** с очисткой Word/Google Docs форматирования (сохраняются заголовки H2–H3, списки, bold/italic, ссылки, таблицы — только для товаров), без замены стилей дизайна сайта.
- **Статусы публикации отделены от видимости**: публикация страницы ≠ показ в каталоге ≠ показ в навигации ≠ показ на главной — каждый флаг независим.
- **Снапшот данных в заказе**: всё, что попало в заказ (название, цена, характеристики, вариация, адрес), фиксируется на момент оформления и не меняется задним числом при редактировании исходной сущности — см. [`orders.md#3-информация-сохраняемая-в-заказе`](./orders.md#3-информация-сохраняемая-в-заказе).
- **Активно vs используется, но неактивно**: почти везде (категории, товары, атрибуты, значения, единицы продажи, производители, страницы) действует одна и та же модель — сущность, уже задействованную где-то, нельзя удалить напрямую, только деактивировать/в корзину; жёсткое удаление возможно только после того, как все связи разорваны.

## Сквозная модель нормализации контактов

Телефон и email клиента сравниваются в **нормализованном** виде при автосвязывании заказов с профилем ([`orders.md#2-оформление-без-регистрации`](./orders.md#2-оформление-без-регистрации), [`customers.md#4-создание-внутреннего-профиля`](./customers.md#4-создание-внутреннего-профиля)): email — без учёта регистра/пробелов, телефон — без пробелов/скобок/дефисов. Автообъединение — только при совпадении **обоих** полей одновременно; при частичном или неоднозначном совпадении создаётся отдельный профиль.

## Открытые вопросы (нужно согласование с заказчиком)

1. Срок хранения категорий/товаров в корзине — бессрочно до ручного удаления или авто-очистка через 30/60 дней (см. [`categories.md`](./categories.md#112-срок-хранения-в-корзине)).
2. Рекомендуемые размеры, пропорции, форматы и макс. размер файла для изображений товара (см. [`products.md`](./products.md#12-изображения)).
3. Требования к фильтрам и атрибутам — детализированы в [`attributes.md`](./attributes.md) (Модуль 6), но некоторые UX-детали каталога могут потребовать доп. согласования.
4. Канал уведомления администратора о новом заказе — предпочтительно Telegram-бот; если это существенно усложняет разработку, нужна альтернатива (например, email) — см. [`orders.md#15-вопрос-для-согласования`](./orders.md#15-вопрос-для-согласования).
5. Порядок обработки запросов на удаление/обезличивание персональных данных клиента — будет определён отдельно, см. [`customers.md#10-удаление-и-персональные-данные`](./customers.md#10-удаление-и-персональные-данные).
