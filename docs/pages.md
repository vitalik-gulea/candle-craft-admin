# Модуль 4. Управление информационными страницами

> Единая простая структура для стандартных страниц: «О нас», «Доставка и оплата», «Контакты», «Политика конфиденциальности» и т.д. Сложный конструктор страниц с блоками/шаблонами не требуется.

## 1. Список страниц

Общий список с колонками:

- название страницы;
- URL;
- статус;
- дата последнего изменения;
- наличие страницы в Header / Footer.

Действия: открыть на редактирование, изменить статус, переместить в корзину. Поиск — простой, по названию.

## 2. Создание и редактирование страницы

Поля:

- [ ] название (RO/RU)
- [ ] URL (RO/RU)
- [ ] содержимое (RO/RU)
- [ ] SEO Title (RO/RU)
- [ ] Meta Description (RO/RU)
- [ ] статус страницы

- Название автоматически используется как H1; в содержимом администратор начинает структуру с H2 (чтобы не было дублей H1 — тот же принцип, что и у категорий/товаров).
- Черновик можно сохранить незавершённым.
- Для публикации обязательны: название, URL и содержимое **на обоих языках**. SEO Title/Meta Description — не обязательны (fallback на усмотрение разработчика: название страницы + автоописание, либо пустой Meta Description — зависит от общей SEO-логики сайта).

## 3. Редактор содержимого

- Тот же WYSIWYG-редактор, что и для описаний товаров/категорий (см. [`categories.md#6-описание-категории-и-визуальный-редактор`](./categories.md#6-описание-категории-и-визуальный-редактор), [`products.md#5-описание-товара`](./products.md#5-описание-товара)).
- Поддерживает: текст, заголовки, списки, ссылки, таблицы, **загрузку изображений прямо в содержимое**.
- Контент редактируется отдельно RO/RU; ALT для изображений — отдельно на каждом языке (пусто, если не заполнено).

## 4. URL и перенаправления

- Автогенерация slugify при создании (RO/RU отдельно), правила транслитерации — те же, что у категорий/товаров.
- Уникальность — среди текущих и ранее использованных (редиректных) адресов.
- Смена названия страницы **не** меняет URL автоматически (защита опубликованных ссылок).
- Ручное изменение URL опубликованной страницы → 301 редирект со старого на новый; все прежние адреса ведут напрямую на актуальный (без цепочек).
- Canonical формируется автоматически на текущий основной URL опубликованной страницы; отдельное ручное поле canonical не нужно.

## 5. Статусы и отображение на сайте

Три статуса: **Черновик** / **Опубликована** / **Скрыта**.

- **Черновик** — доступен только в админке.
- **Опубликована** — доступна по URL, может быть добавлена в Header/Footer.
- **Скрыта** — сохраняется в админке, но недоступна посетителям, не в sitemap, автоматически не отображается в Header/Footer. После повторной публикации пункт меню может вернуться, если не был отдельно отключён в настройках меню.

## 6. Корзина и удаление

- Удаление — через корзину, как и для других сущностей (см. паттерн в [`categories.md#11-удаление-и-восстановление-категории`](./categories.md#11-удаление-и-восстановление-категории)); перед перемещением в корзину — подтверждение.
- Если страница используется в Header/Footer — предупреждение; после подтверждения её пункты меню автоматически скрываются/удаляются из меню.
- Восстановление из корзины → статус «Черновик», **не** возвращается в меню автоматически.
- Финальное удаление опубликованной страницы: можно указать страницу для редиректа 301; если не задано — 410 или 404. Авторедирект на главную — не требуется.

## 7. Управление Header и Footer

- Публикация страницы **не** добавляет её в меню автоматически.
- В настройках Header/Footer администратор может:
  - выбирать информационные и доступные системные страницы для соответствующего меню;
  - добавить одну и ту же страницу одновременно в Header и Footer;
  - менять порядок пунктов drag & drop;
  - временно скрыть пункт меню, не скрывая/не удаляя саму страницу.
- Название пункта меню по умолчанию = название страницы на соответствующем языке (кастомное название пункта меню — не требуется на первом этапе).
- В меню нельзя вывести страницу со статусом «Черновик», «Скрыта» или находящуюся в корзине.

## 8. Страница «Контакты» и контактные данные

- Страница «Контакты» создаётся/редактируется в этом модуле как обычная информационная страница.
- Но сами контактные данные сайта — в **одном общем разделе настроек** (не дублируются отдельно на странице / в Footer / где-либо ещё):
  - адрес (RO/RU);
  - номер телефона;
  - график работы (RO/RU);
  - ссылка на карту.
- Эти данные автоматически используются на странице «Контакты» и в других местах по дизайну.
- Доп. содержимое страницы «Контакты» (текст, изображение) редактируется через общий редактор, отдельно RO/RU.
- Форма обратной связи на странице «Контакты» — не требуется.

## 9. Системные страницы

- Homepage, Catalog, Cart, Checkout, Account, страница результатов поиска — **системные**: не создаются/не удаляются/не редактируются как обычные инфостраницы.
- При этом доступные системные страницы можно добавлять в Header/Footer, менять их порядок и временно скрывать пункты меню (если это предусмотрено структурой сайта).
