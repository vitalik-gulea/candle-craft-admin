# Модуль 1. Управление категориями каталога

> Версии сайта RO/RU. Структура каталога будет предоставлена отдельным документом.

## 1. Общие положения

- Все поля с текстом или URL редактируются **отдельно** для RO и RU.
- Если информация уже введена в карточке категории, она переиспользуется на других участках сайта без повторного ввода (например, в сетке категорий на главной).

## 2. Поля категории

- [ ] название категории (RO / RU)
- [ ] URL (RO / RU)
- [ ] родительская категория (выбор)
- [ ] изображение категории
- [ ] ALT-текст изображения (RO / RU)
- [ ] описание категории (RO / RU, WYSIWYG)
- [ ] SEO Title (RO / RU)
- [ ] Meta Description (RO / RU)
- [ ] статус публикации категории
- [ ] отображение в каталоге (флаг)
- [ ] отображение в навигации (флаг)
- [ ] отображение на главной странице (флаг)
- [ ] параметр «Показывать товары из подкатегорий»
- [ ] блок FAQ (RO / RU, необязательный)

## 3. Формирование URL

### 3.1. Общие требования

- Автогенерация из названия через `slugify` при создании; после создания редактируется вручную отдельно для RO/RU.
- Правила: только латиница/цифры/дефисы; румынская диакритика → латиница без диакритики; кириллица → транслитерация; пробелы → дефисы; без служебных/закодированных символов; URL короткий и читаемый.

**Примеры:**

| Исходное название | URL |
|---|---|
| Ceară pentru lumânări | `ceara-pentru-lumanari` |
| Fitiluri și accesorii | `fitiluri-si-accesorii` |
| Воск для свечей | `vosk-dlya-svechey` |

### 3.2. Изменение названия и URL

- Смена названия категории **не** меняет существующий URL автоматически.
- При ручном изменении URL опубликованной категории:
  - создаётся редирект 301 со старого на новый URL, отдельно для RO/RU;
  - все ранее использованные URL редиректят напрямую на текущий (без цепочек);
  - циклические редиректы запрещены;
  - редирект не создаётся, если URL фактически не изменился;
  - лимита на количество сохранённых старых URL нет.
- **Желательно:** история старых URL категории, видимая в админке.

### 3.3. Уникальность URL

- Уникален в пределах языковой версии.
- При конфликте — предупреждение и блокировка сохранения.
- Автодобавление `-2`/`-3` без подтверждения администратора запрещено.
- Проверка уникальности учитывает и текущие, и старые (редиректные) URL.

### 3.4. URL и иерархия каталога

- URL категории **не зависит** от положения в иерархии и не включает URL родителя.
  - Пример: `/ceara-de-soia/`, а не `/ceara-pentru-lumanari/ceara-de-soia/`.
- Перемещение категории в другого родителя не меняет её URL.

## 4. Иерархия, порядок и хлебные крошки

- Категория — первого уровня либо подкатегория; родитель задаётся в настройках.
- Порядок категорий/подкатегорий — вручную, drag & drop; новая категория вставляется в нужное место без пересчёта порядка остальных.
- Хлебные крошки строятся автоматически по иерархии (родительским связям), **независимо от структуры URL**.
  - Пример: Главная → Каталог → Воск для свечей → Соевый воск.

## 5. Связь категорий с товарами

- Товар может входить в несколько категорий; одна из них — **основная**.
- Основная категория обязана входить в список выбранных категорий товара.
- Если товар удаляют из основной категории — система требует выбрать новую основную.
- Основная категория используется для хлебных крошек страницы товара.
- Товар привязывается к самой конкретной подкатегории; вручную дублировать во все родительские категории не нужно.
- Товар подкатегории автоматически показывается на странице родителя, если у родителя включено «Показывать товары из подкатегорий».
  - Пример: Главная → Каталог → Воск для свечей → Соевый воск → Название товара.

## 6. Описание категории и визуальный редактор

- Описание (RO/RU) отображается под списком товаров категории.
- WYSIWYG-редактор: вставка форматированного текста из Word/Google Docs без ручной правки HTML.
- При вставке сохраняются: абзацы/переносы, заголовки H2–H3, bold/italic, списки (маркированные/нумерованные), встроенные ссылки.
- Редактор автоматически чистит служебный код/стили Word; шрифты/размеры/цвета из Word не переопределяют дизайн сайта.
- Для ссылок: задать/изменить URL, открыть в текущей/новой вкладке, удалить ссылку без удаления текста.
- На странице категории — ровно один H1 (из названия категории); в описании — заголовки от H2.

## 7. Блок FAQ

- Несколько вопрос-ответов, редактируемых отдельно для RO/RU.
- Удаление отдельных вопросов; порядок — drag & drop.
- Пустые вопросы/ответы не отображаются; блок скрыт целиком, если вопросов нет.
- **Желательно:** структурированные данные FAQ (schema.org), если técnически возможно и актуально для SEO.

## 8. Статусы и видимость категории

Разделённые независимые флаги:

- публикация страницы категории;
- отображение в каталоге;
- отображение в навигации;
- отображение на главной.

- Скрытие из каталога/навигации/главной **не** отключает и не удаляет страницу.
- Категория в статусе «Черновик»/«Не опубликована»: страница недоступна пользователям, не в каталоге/навигации/главной, не в sitemap. Правило наследуется — неопубликованные дочерние категории тоже скрыты от пользователей.

## 9. Изображение категории

- Загрузка и замена изображения.
- Удаление изображения из карточки.
- ALT-текст отдельно RO/RU.
- Отображение рекомендуемого размера/формата в самой админке (подсказка для оператора).

## 10. Отображение категории на Homepage

- Флаг «Показывать на главной странице».
- Порядок категорий на главной — отдельный drag & drop, **не** влияет на порядок в каталоге/навигации.
- Название/ссылка/изображение для сетки на Homepage берутся из карточки категории без повторного ввода.

## 11. Удаление и восстановление категории

- Удаление → сначала в корзину (не отображается на сайте) → восстановление или окончательное удаление вручную.
- Если в категории есть товары/подкатегории — предупреждение перед перемещением в корзину.
- Перед окончательным удалением система проверяет:
  - есть ли товары;
  - есть ли подкатегории;
  - является ли категория основной для каких-либо товаров;
  - есть ли связанные редиректы.
- До удаления нужно определить, куда переносятся подкатегории/товары и какая категория станет основной для этих товаров.
- Изображение категории **не** удаляется автоматически из медиатеки (может использоваться в других местах).

### 11.1. Старый URL удалённой категории

- При финальном удалении опубликованной категории администратор указывает страницу для редиректа 301.
- Без подходящей страницы — статус 410 (без авторедиректа на главную).
- Выбранное правило (редирект/410) применяется и к текущему URL, и ко всем ранее сохранённым URL этой категории.

### 11.2. Срок хранения в корзине

- Предпочтительно: без авто-удаления (данные занимают мало места, восстановление может понадобиться).
- Альтернатива: авто-очистка через 30 или 60 дней с предупреждением перед финальным удалением.
- **Вопрос для согласования:** бессрочное хранение до ручного удаления vs авто-очистка 30/60 дней.

## 12. Фильтры и атрибуты

- Требования будут предоставлены отдельно, после согласования функционала категорий и товаров.

## 13. Итоговые требования к административному списку

В общем списке категорий (желательно):

- иерархия категорий/подкатегорий;
- название;
- статус публикации;
- отображение в каталоге;
- отображение на главной;
- быстрый переход к редактированию;
- изменение порядка/иерархии drag & drop.
